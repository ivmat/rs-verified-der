# gates/map_declared.txt — DECLARED (non-derivable) verification-map nodes.
#
# `gates/gen_verification_map.py` renders `README.md`'s GENERATED:map region. Every COLOURED node
# there is an assurance BAND read from `der-verified/acceptance.toml` (the generated acceptance/0
# manifest) and can never drift, because it is re-read on every run. The nodes in THIS file are the
# opposite case: places where the manifest carries no claim at all, and the reason it does not is a
# human's read of the project's own prose. They render as white dashed boxes — never as a band,
# because nothing was measured — one row per node.
#
# FORMAT: one row per node, TAB-separated, exactly 5 fields:
#
#     <class>\t<id>\t<layer>\t<label>\t<source>
#
#   class  — one of: planned (intended, whether or not started), wall (a known hard
#            tool/expressiveness blocker we hit), out-of-scope (a recorded scope decision).
#            NEVER a band (A0..A4): bands are derived from the manifest, never declared here.
#   id     — a mermaid-safe identifier (`^[a-z][a-z0-9_]*$`). MUST NOT collide with a module
#            name in `gates/tiers.txt` — `gen_verification_map.py`'s parity check fails closed
#            on that, because a same-named declared node would silently shadow a real one.
#   layer  — which subgraph of the diagram this node is drawn in: crypto, profile, structural,
#            codecs, framing (see `gen_verification_map.py`'s LAYERS).
#   label  — the human-readable text drawn in the node box.
#   source — REQUIRED. A file (and section/line/heading) a reader can open to check this
#            judgement themselves. A row with no source is a row nobody can audit, so the
#            script refuses to load a row missing one — leave a row out entirely rather than
#            add one you cannot cite.
#
# Comment lines (leading `#`) and blank lines are ignored. Column order is fixed; do not reorder.
